## 1. VULNERABILIDADES CRITICAS

### 1.1 Sin autenticacion en ningun endpoint

- **Archivos**: `backend/app/main.py`, todos los routers en `backend/app/api/`
- **Impacto**: Cualquier usuario en la red puede acceder a todos los endpoints: subir ficheros, ejecutar analisis, leer/borrar datos, modificar configuracion.
- **Agravante**: El endpoint `POST /api/v1/admin/reset` en `backend/app/api/admin.py` borra toda la base de datos sin autenticacion.
- **Recomendacion**: Implementar middleware JWT/API-Key. Minimo: proteger admin y settings.

### 1.2 XSS via dangerouslySetInnerHTML

- **Archivos**: `frontend/src/routes/Architecture.tsx:23-41`, `frontend/src/routes/Data.tsx:95`
- **Impacto**: Si las traducciones i18n se cargan desde el backend (`GET /api/v1/i18n/{lang}`) y un atacante inyecta HTML/JS en esas respuestas, se ejecuta codigo arbitrario en el navegador.
- **Mitigacion actual**: Ninguna. El comentario dice "i18n statique de confiance" pero el dato viene del backend.
- **Recomendacion**: Reemplazar `dangerouslySetInnerHTML` por DOMPurify o renderizar traducciones como texto plano.

### 1.3 Cifrado de secretos opcional

- **Archivo**: `backend/app/core/encryption.py:72-75`, `backend/app/config.py:69`
- **Impacto**: Si `ENCRYPTION_KEY` no se configura, la clave API de Mistral se almacena en texto plano en SQLite (tabla `app_config`).
- **Codigo afectado**:
  ```python
  if not self._enabled or not self._cipher:
      logger.warning("Encryption disabled - storing plaintext (INSECURE)")
      return plaintext  # devuelve en claro
  ```
- **Recomendacion**: Hacer el cifrado obligatorio. Fallar en startup si `ENCRYPTION_KEY` no esta configurado.

## 2. BRECHAS DE SEGURIDAD (ALTO / MEDIO)

| Severidad | Brecha | Ubicacion | Detalle |
|-----------|--------|-----------|---------|
| **ALTO** | CORS hardcoded con localhost | `backend/app/config.py:45-49` | Origenes incluyen `localhost:5173` fijo. En produccion deberia leerse exclusivamente de `.env`. |
| **ALTO** | Prompt injection parcial | `backend/app/api/settings.py:225`, `backend/app/checks/custom_rules.py:185` | El sanitizador de prompts existe (`prompt_sanitizer.py`) pero NO se aplica en todas las llamadas al LLM. |
| **MEDIO** | Rate limiting spoofable | `backend/app/main.py:32` | Usa `get_remote_address` que lee `X-Forwarded-For` — spoofable sin proxy de confianza configurado. |
| **MEDIO** | Sin CSRF token en frontend | `frontend/src/lib/api.ts` | Ningun token CSRF en las peticiones. Depende de que el backend use `SameSite` cookies (no verificado). |
| **MEDIO** | SSE streams sin timeout | `frontend/src/lib/api.ts:244-329` | El streaming del chat no tiene timeout — un stream colgado bloquea la UI indefinidamente. |
| **BAJO** | Modelos Mistral hardcoded | `backend/app/config.py:36-38` | Si la API cambia nombres de modelo, la app se rompe sin redespliegue. |

## 3. PROBLEMAS DE RENDIMIENTO

| Severidad | Problema | Ubicacion | Solucion |
|-----------|----------|-----------|----------|
| **MEDIO** | N+1 queries en busqueda de ficheros | `backend/app/api/files.py:94` | Loop Python `for f in project.files` para buscar por nombre. Usar `WHERE` SQL. |
| **MEDIO** | N+1 en custom_rules | `backend/app/checks/custom_rules.py:116` | Itera `project.files` con lazy loading. Usar `selectinload()`. |
| **MEDIO** | I/O bloqueante en contexto async | `backend/app/api/chat.py:113-137` | `db.add()` y `db.commit()` sincronos dentro de funcion `async`. Bloquea el event loop. |
| **MEDIO** | Embeddings secuenciales | `backend/app/api/analysis.py:135-141` | Un fichero a la vez en loop sincrono. Usar batch o async paralelo. |
| **MEDIO** | Indice faltante en Anomaly.status | `backend/app/db/models.py` | Campo filtrado frecuentemente (chat_engine, anomalies) sin `index=True`. |
| **BAJO** | Sin code-splitting en frontend | `frontend/vite.config.ts` | Todas las rutas en un solo bundle. `react-router` lazy imports mejorarian TTI. |

## 5. HALLAZGOS POSITIVOS

- Proteccion contra path traversal solida: `safe_storage_join()` valida rutas correctamente.
- Validacion de magic bytes en uploads (MIME type checking).
- Sin SQL injection: SQLAlchemy ORM en todo el backend, sin SQL crudo.
- Sanitizacion de filenames con `safe_filename()`.
- Error handling estructurado sin leakage de stack traces.
- Request ID propagado end-to-end (`X-Request-Id`).
- Zustand + React Query bien implementados en frontend.
- Validacion con Zod en formularios.
- Double-click confirmation pattern (sin `alert()`/`confirm()`).
- `ErrorBoundary` en React correctamente implementado.
- Timestamps con `datetime.now(timezone.utc)` — buena practica para audit trails.
- Truststore integrado para manejo moderno de certificados SSL.
